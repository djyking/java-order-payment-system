## 2. 已实现但仍需生产化

| 项目 | 当前状态 | 生产化要求 |
|---|---|---|
| Nacos 配置中心 | 服务已连接，但当前 dataId 为空 | 开启鉴权，将配置分环境持久化并纳入变更审计 |
| Sentinel 规则 | 本地规则真实生效 | 接入 Nacos 规则数据源，避免实例重启或多实例规则漂移 |
| 支付 | 完整支付单和幂等回调链路，渠道为 Mock | 接真实渠道签名验签、退款、对账文件和资金差错处理 |

## 3. 配置或可选扩展

Elasticsearch、Kubernetes、真实支付渠道、自动扩缩容当前未实现。它们不是现阶段订单一致性主链路的必要条件，不能在项目介绍中声称已经具备。

## 4. 明显风险

1. 支付成功晚于关单时，系统能阻止库存售出并登记 `PAY_SUCCESS_AFTER_ORDER_CLOSED`，但尚无自动退款或人工工单闭环。
2. 自动化测试数量仍少：当前只有库存防超卖、订单状态机和支付幂等共 4 个测试用例；故障验收主要是本机运行记录。
3. 本地 Compose 默认口令和关闭鉴权只适合开发验收，不能直接作为生产配置。
4. 单机 50 QPS Sentinel 上限会使 50 RPS 边界出现约 1.6% 拒绝；应根据容量评估设置生产阈值，而不是简单调高。
