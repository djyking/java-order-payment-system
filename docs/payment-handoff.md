# 支付接入交接

本阶段建立用户购买与管理员处理业务，以及按支付方式选择适配器的接口。真实渠道的下单、查单、关闭、通知验签、退款和账单核对在支付阶段实现并验证。

## 接入方式

`order-payment-service` 的 `PaymentProvider` 是渠道边界。业务订单使用稳定订单号与服务端计算的分币金额；前端只能选择服务端公布的方式，不能传入金额或把浏览器跳转作为支付成功依据。

预置方式代码：`ALIPAY_PAGE`（支付宝网页支付）、`WECHAT_NATIVE`（微信扫码支付）。账号条件确定后，可增加支付宝手机网站支付、微信 JSAPI/H5，或实现调用已有个人支付服务的适配器；每个代码代表具体支付产品，而不只是品牌名称。

真实方式在本版返回不可用状态。填写配置不会自动开启尚未实现的渠道适配器。`MOCK` 仅在显式设置 `PAYMENT_MOCK_ENABLED=true` 的开发环境开放，用于内部状态处理测试，不代表收款。一个业务订单复用一个支付单；已有活动支付单时禁止直接换渠道。下一阶段先完成渠道查单/关单及原支付尝试关闭确认，再开放换支付方式，避免重复付款。

## 下一轮需确认的信息

1. **账号与支付产品**：选择支付宝、微信，或已有支付服务；提供账号类型（个人/个体工商户/企业）、已开通的具体支付产品以及沙箱/测试环境。普通个人收款码不等同于支持服务端回调的支付 API，须以账户实际签约能力为准。
2. **文档与非秘密标识**：对应 API 文档地址、应用 ID、商户号；若对接已有支付服务，还需基础地址、认证方式、支付方式清单，以及下单/查询/关单/退款/通知契约和示例。
3. **本机密钥配置**：支付宝应用私钥与平台验签公钥/证书；微信商户 API 私钥、证书序列号、API v3 密钥与平台验签材料，具体按实际产品要求确定。密钥填入本机忽略文件、环境变量或密钥服务，不写入前端或 GitHub。无需把原始私钥粘贴进聊天。
4. **可访问地址**：测试回调的 HTTPS 地址、前端返回地址及部署域名；微信 JSAPI 等还需满足对应授权目录、AppID 绑定及用户身份条件。
5. **业务规则**：实际售卖内容、金额范围、订单过期时间、交付方式与退款规则。

## 下一阶段验收顺序

先接一个已开通的沙箱/测试渠道，再用相同契约接第二种方式。依次验证下单、签名验签、重复与乱序通知、主动查单、通知丢失恢复、支付与超时关闭竞争、渠道切换、全额退款与退款重试、账单核对。接着串联支付完成后的管理员处理与用户确认，最后才做经授权的小额真实交易。

浏览器支付按钮、返回页参数和测试入口都不能作为真实支付成功凭据。支付成功、订单交付和退款应各自保留独立状态与审计记录。
